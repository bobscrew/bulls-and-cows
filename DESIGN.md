# Design Document: Bulls and Cows

## 1. Структуры данных и алгоритмы

### Состояние игры (Game State)
Состояние игры представлено интерфейсом `GameState` (`src/state.ts`):
- `settings`: Объект, содержащий `length` (количество цифр) и `base` (система счисления).
- `secret`: Строка, представляющая секретное число (например, "0123").
- `history`: Массив объектов `Attempt`. Каждая попытка хранит угаданную строку и результат bulls/cows.
- `status`: Union-тип (`'settings' | 'playing' | 'won'`) для отслеживания текущего экрана.
- `startTime`: Временная метка для расчета затраченного времени.

**Почему иммутабельность?**
История обновляется с помощью оператора расширения (`[...state.history, newAttempt]`), а не через `push()`. Это гарантирует, что обновления состояния предсказуемы и чисты, избегая побочных эффектов и упрощая отладку и тестирование.

### Алгоритм `evaluateGuess`
Алгоритм сравнивает две строки (секрет и попытку) и считает быков и коров.
1. Обе строки приводятся к нижнему регистру и разбиваются на массивы, чтобы корректно обрабатывать hex-цифры (например, 'A' и 'a' считаются одинаковыми).
2. **Быки (Bulls)** считаются через `reduce`: мы проходим по массиву попытки и считаем, сколько символов совпадают с символом секрета на той же позиции.
3. **Коровы (Cows)** считаются путем фильтрации символов попытки, которые есть в массиве секрета. Общее количество совпадений минус быки дает коров.
Этот подход использует функции высшего порядка (HOF) и избегает ручных циклов `for`.

### Алгоритм `countPossibleSecrets`
Эта функция вычисляет количество перестановок без повторений: \(P(base, length) = \frac{base!}{(base - length)!}\).
- **Рекурсия**: Функция определена рекурсивно как `base * countPossibleSecrets(length - 1, base - 1)`.
- **Базовые случаи**: Если `length === 0`, вернуть 1. Если `length > base`, вернуть 0.
- **Мемоизация**: Объект `memo` используется для кэширования результатов по ключу `length-base`. Это предотвращает повторные вычисления одних и тех же перестановок при многократном открытии экрана настроек.

## 2. Сложность (Big O)

- **`generateSecret(length, base)`**: **O(length)**. Функция рекурсивно выбирает уникальные символы. В худшем случае она выполняет `length` итераций, а срезы массива занимают O(base) времени на шаг, но так как `length` мала (макс. 6), это практически константа.
- **`evaluateGuess(secret, guess)`**: **O(n)**. Методы `reduce` и `filter` проходят по массиву попытки один раз. `includes` внутри `filter` в худшем случае добавляет O(n), что делает сложность O(n²), но так как `n` мало (макс. 6), это незначительно.
- **`isValidGuess(guess, length, base)`**: **O(n)**. Преобразование в Set и проверка длины занимает O(n) времени.
- **`countPossibleSecrets(length, base)`**: **O(length)**. С мемоизацией первый вызов занимает O(length) из-за рекурсии. Последующие вызовы — **O(1)**, так как берутся из кэша.

## 3. Принципы чистого кода (Clean Code)

- **Чистые функции (Pure Functions)**: Весь файл `src/core.ts` состоит из чистых функций. Они не мутируют внешнее состояние, не зависят от DOM и возвращают одинаковый результат для одинаковых входных данных.
- **Функции высшего порядка (HOF)**: Широко используются в `evaluateGuess` (`reduce`, `filter`) и `createDigitValidator` (возвращает функцию).
- **Каррирование (Currying)**: `createDigitValidator(base)` возвращает функцию `(char) => boolean`. Это позволяет создавать конкретные валидаторы один раз и переиспользовать их для фильтрации ввода и валидации.
- **Иммутабельность (Immutability)**: Обновления состояния в `src/state.ts` всегда возвращают новый объект с помощью оператора расширения, никогда не изменяя исходный.
